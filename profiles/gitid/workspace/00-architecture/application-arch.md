## 第一部分：文档概述

将业务架构映射为应用域、功能模块与功能子模块。gitid 是本机双端工具（CLI + 桌面），无服务端；应用域按 DDD 四层归类，平台支撑域承载自动更新、界面语言与命令补全（BA 未列的纯技术能力）。

### 1.1 背景与目标

在不引入守护进程与 git 钩子的前提下，把「档案 / 应用 / 扫描处置 / 历史核验 / 体检」组织为可追溯到 BA 的功能模块，并标出个人开发者在各模块上的操作面。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 将业务架构映射为应用域、功能模块、功能子模块的层级结构，标注用户类型、模块间调用关系及应用域分层 |
| 本文档不做什么 | 不涉及具体功能点描述、不涉及系统详细设计、不涉及技术实现和部署方案 |

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 业务域 | Git 多身份管理 |
| 应用域 | 核心业务域、支撑业务域、基础数据域、平台支撑域 |
| 用户类型 | 个人开发者 |

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

核心域承担档案、应用、扫描、处置与历史审计；支撑域承担凭据管道、远程镜像与环境体检；基础域只有本机设置；平台域提供自动更新、国际化与 shell 补全。所有业务写入仍汇聚到单一核心，CLI 与桌面只做交互。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 L3 → DDD 四层归类原则归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有状态机和聚合根，深度建模 | 身份档案管理、全局身份应用、仓库身份应用、仓库配置扫描、扫描结果处置、提交历史身份审计 |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 凭据管道、远程与镜像、环境体检 |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | 本机设置 |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | 桌面自动更新、界面与文档国际化、CLI 命令补全 |

### 2.1 核心业务域

## 第三部分：应用架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：应用域 > 功能模块 > 功能子模块（含功能说明）。

```
gitid
├── 核心业务域
│   ├── 身份档案管理
│   │   ├── 新建与更新身份 — 按 id 写入档案（含签名格式）
│   │   ├── 导入全局配置为档案 — 从全局 git 收编
│   │   ├── 收编扫描手配为档案 — 从 ⚠ 行写入档案
│   │   ├── 删除身份 — 只删档案
│   │   ├── 查阅身份列表 — 无状态匹配展示
│   │   └── 声明签名格式 — openpgp|ssh|x509
│   ├── 全局身份应用
│   │   └── 全量覆盖写入全局 — use 默认作用域
│   ├── 仓库身份应用
│   │   ├── 写入当前仓库本地 — use --local / local
│   │   ├── 批量写入选定仓库 — --repos / 桌面多选
│   │   └── 清除本地覆盖 — unset 回退全局
│   ├── 仓库配置扫描
│   │   ├── 扫描目录仓库 — 发现 .git
│   │   ├── 匹配并标记扫描结果 — ✓/✗/⚠/◆/⊕
│   │   ├── 导出扫描报告 — json/markdown/csv
│   │   └── 保存默认扫描范围 — settings
│   ├── 扫描结果处置
│   │   ├── 对手配发起收编 — 组合收编
│   │   └── 对缺失发起批量应用 — 组合批量本地写
│   └── 提交历史身份审计
│       ├── 聚合作者分布 — git log
```
