## 第一部分：文档概述

gitid 帮助个人开发者在本机管理多套 git 提交身份，把档案应用到全局或仓库本地，并审计目录内仓库的身份是否配错、配漏或与档案不一致。本次增量把「只扫描」升级为「扫描后可处置」，并补齐签名格式、历史作者核验与环境体检。

### 1.1 背景与目标

个人开发者通常持有公司/个人/客户现场等多套 name+email（及可选签名）。配错邮箱会把个人提交写进公司历史。gitid 以 git 自身配置为事实源，档案与生效配置分离，不做后台切换。

上一轮增量补齐了扫描后处置、历史作者核验与环境体检。本次增量目标：把「目录树默认身份」交给 git 原生 `includeIf.gitdir`，新 clone 不必再逐仓写 local。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 描述 Git 多身份管理域内 L2/L3/L4 的层级结构和业务关系，不涉及系统实现 |
| 本文档不做什么 | 不划分应用模块、不标注用户类型、不涉及技术选型和系统架构 |

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

开发者先把常用提交者信息收进档案库，再按需要应用到全局、某个仓库，或绑定到一棵目录树；随后扫描工作目录，对照档案看每个仓库是否缺失、手配或已对齐，并展示生效来自本地、目录绑定还是全局。凭据与远程镜像仍由 git 自身机制承载。目录绑定由 git 计算生效，gitid 只生成与回收 include 片段。

### 2.1 身份建档与维护

**业务说明**：把可复用的提交者档案集中存放，与 git 当前生效配置分离。包含新建、更新、从已有配置导入、删除与查阅。所属阶段覆盖日常档案维护。

##### 2.1.1 身份档案管理

**业务说明**：维护本机档案库中的身份（id、姓名、邮箱、签名键、是否强制签名、签名格式、URL 重写、凭据账号选择器、自定义键）。所属 L2：身份建档与维护。

###### 2.1.1.1 新建与更新身份

**业务说明**：按 id 写入或覆盖一条档案；姓名与邮箱必填；签名相关字段可选。所属 L3：身份档案管理。

###### 2.1.1.2 导入全局配置为档案

**业务说明**：把当前全局 git 的 name/email/签名配置收成一条档案，避免从零录入。所属 L3：身份档案管理。

###### 2.1.1.3 收编扫描手配为档案

**业务说明**：把扫描中「生效 name+email 未命中任何档案」的仓库配置收编进档案库；已命中的跳过；无名邮的缺失仓库不可收编。所属 L3：身份档案管理。

###### 2.1.1.4 删除身份

**业务说明**：从档案库移除一条身份，不改已经写入全局或仓库本地的身份键。若该身份仍有目录绑定，先回收其 include 片段再删档案。所属 L3：身份档案管理。

###### 2.1.1.5 查阅身份列表

**业务说明**：列出全部档案，并对照当前全局/当前仓库生效值做无状态匹配展示；同时展示该身份已绑定的目录树。所属 L3：身份档案管理。

###### 2.1.1.6 声明签名格式

**业务说明**：身份可声明签名格式（openpgp / ssh / x509），与签名键一并保存；未声明则该身份不携带格式。所属 L3：身份档案管理。

### 2.2 身份生效

**业务说明**：把档案写入 git 配置并立即按 git 自身规则生效（本地覆盖优先于目录绑定，再回退全局）。切换时未再声明的签名、格式、重写与选择器必须清除，避免上一身份残留。目录绑定不把规则写入全局配置正文。

##### 2.2.1 全局身份应用

**业务说明**：把选定档案写入全局 git 配置，作为无本地覆盖仓库的回退身份。所属 L2：身份生效。

###### 2.2.1.1 全量覆盖写入全局

**业务说明**：写入 name/email 及档案声明的可选键；档案未声明的签名键、签名开关、签名格式、额外键、URL 重写、凭据选择器一律清除。若该身份已有目录绑定，同步刷新其 include 片段内容，不增删绑定。所属 L3：全局身份应用。

##### 2.2.2 仓库身份应用

**业务说明**：把选定档案写入一个或多个仓库的本地配置，或清除本地覆盖以回退全局。所属 L2：身份生效。

###### 2.2.2.1 写入当前仓库本地

**业务说明**：仅对当前仓库做与全局应用相同的全量覆盖。所属 L3：仓库身份应用。

###### 2.2.2.2 批量写入选定仓库

**业务说明**：对扫描结果或显式指定的一组仓库逐个写入本地身份（典型对象为配置缺失的仓库）。所属 L3：仓库身份应用。

###### 2.2.2.3 清除本地覆盖

**业务说明**：去掉仓库本地身份键，此后该仓库按 git 规则回退到目录绑定或全局。所属 L3：仓库身份应用。

##### 2.2.3 目录级身份绑定

**业务说明**：把档案绑定到一棵目录树，由 git 的目录条件决定该树下仓库的默认身份，介于仓库本地与全局之间。所属 L2：身份生效。不监视目录、不在后台切换身份。

###### 2.2.3.1 绑定目录树

**业务说明**：为选定身份登记一条目录前缀，立即生成独立 include 片段并挂到全局配置的 include 钩子上；同一规范化路径不可同时属于两个身份。所属 L3：目录级身份绑定。

###### 2.2.3.2 解除目录绑定

**业务说明**：去掉身份上的一条或全部目录登记，并回收对应 include 片段；无剩余绑定且无其他身份需要时，钩子文件可留空但不把目录规则写回全局配置正文。所属 L3：目录级身份绑定。

### 2.3 仓库审计与处置

**业务说明**：在指定目录发现 git 仓库，对照档案判断每个仓库的生效身份，并允许对问题仓库收编或补齐；进一步可核验提交历史作者是否混用了另一套邮箱。

##### 2.3.1 仓库配置扫描

**业务说明**：按目录与深度发现仓库，读取各仓生效/本地身份与远程状态，与档案做 name+email 匹配。所属 L2：仓库审计与处置。

###### 2.3.1.1 扫描目录仓库

**业务说明**：在根目录下发现 git 仓库（遇仓库即停、不进入仓库内部），记录路径与生效配置。所属 L3：仓库配置扫描。

###### 2.3.1.2 匹配并标记扫描结果

**业务说明**：标记正常、配置缺失、手配、本地覆盖、镜像推送，以及生效来自目录绑定的标记；来源必须与 git 真实优先级一致。所属 L3：仓库配置扫描。

###### 2.3.1.3 导出扫描报告

**业务说明**：把同一次扫描结果导出为可被脚本或团队消费的结构化报告。所属 L3：仓库配置扫描。

###### 2.3.1.4 保存默认扫描范围

**业务说明**：记住常用扫描目录与深度，下次裸扫描直接使用。所属 L3：仓库配置扫描。

##### 2.3.2 扫描结果处置

**业务说明**：在扫描结果上发起收编（⚠）或批量应用（✗），闭环回到档案管理与仓库身份应用，不引入「已处理」持久标记。所属 L2：仓库审计与处置。

###### 2.3.2.1 对手配发起收编

**业务说明**：从当前扫描结果中选出手配仓库，执行「收编扫描手配为档案」。所属 L3：扫描结果处置。

###### 2.3.2.2 对缺失发起批量应用

**业务说明**：从当前扫描结果中选出配置缺失仓库，执行「批量写入选定仓库」。所属 L3：扫描结果处置。

##### 2.3.3 提交历史身份审计

**业务说明**：用仓库已有提交记录聚合作者 name/email 分布，对照档案回答是否混入另一套邮箱；只读，不改写历史。所属 L2：仓库审计与处置。

###### 2.3.3.1 聚合作者分布

**业务说明**：统计该仓库历史中各作者 name/email 的出现次数。所属 L3：提交历史身份审计。

###### 2.3.3.2 对照档案标注

**业务说明**：将每个作者对与档案匹配；可选指定期望身份，把邮箱不同的作者标为污染。所属 L3：提交历史身份审计。

###### 2.3.3.3 生成 mailmap 建议

**业务说明**：针对同一邮箱的不同作者名（或明确的污染对）给出 `.mailmap` 文本建议，仅展示不落盘。所属 L3：提交历史身份审计。

### 2.4 协作通道维护

**业务说明**：管理不存储密钥的协作配置（凭据账号选择、远程镜像），并体检本机 git 环境是否具备签名与推送所需条件。

##### 2.4.1 凭据管道

**业务说明**：只做「选哪个账号」和把一次性口令交给 git 凭据助手；本体不进档案。所属 L2：协作通道维护。

###### 2.4.1.1 登录与保存凭据

**业务说明**：经助手完成登录或写入口令。所属 L3：凭据管道。

###### 2.4.1.2 列出与移除凭据线索

**业务说明**：按 host+username 展示助手是否已存，并允许移除；不展示口令。所属 L3：凭据管道。

##### 2.4.2 远程与镜像

**业务说明**：查看仓库远程，并为某个远程增加或取消镜像推送地址。所属 L2：协作通道维护。

###### 2.4.2.1 查看远程

**业务说明**：列出 fetch/push 地址与是否镜像。所属 L3：远程与镜像。

###### 2.4.2.2 启用或取消镜像推送

**业务说明**：为指定远程配置或清除额外 push 目标。所属 L3：远程与镜像。

##### 2.4.3 环境体检

**业务说明**：只读检查本机是否具备使用身份、签名与凭据所需的环境条件，指出对不上或互相冲突的规则。所属 L2：协作通道维护。

###### 2.4.3.1 检查 git 版本

**业务说明**：确认 git 可执行且版本可用。所属 L3：环境体检。

###### 2.4.3.2 检查凭据助手是否在位

**业务说明**：确认已配置助手且对应程序可被探测到。所属 L3：环境体检。

###### 2.4.3.3 对照 SSH 别名与地址重写

**业务说明**：比对 SSH 配置中的 host 别名与身份里的地址重写是否指向同一目标。所属 L3：环境体检。

###### 2.4.3.4 检测地址重写冲突

**业务说明**：找出同一原始地址对应多条不同重写、或规则互相覆盖的情况。所属 L3：环境体检。

### 附录A：L3 业务依赖关系

> 描述 L3 关键业务之间的上下游依赖关系，为后续应用架构中模块调用分析提供依据。

| 上游 L3 | 依赖方向 | 下游 L3 | 依赖说明 |
|---------|---------|---------|---------|
| 身份档案管理 | → | 全局身份应用 | 应用时读取档案字段并全量覆盖 |
| 身份档案管理 | → | 仓库身份应用 | 同上，作用域为仓库本地 |
| 身份档案管理 | → | 目录级身份绑定 | 绑定读取档案字段并物化 include 片段 |
| 目录级身份绑定 | → | 仓库配置扫描 | 扫描按 git 来源标注目录绑定 |
| 仓库配置扫描 | → | 扫描结果处置 | 处置输入为当次扫描行 |
| 扫描结果处置 | → | 身份档案管理 | 收编写档案库 |
| 扫描结果处置 | → | 仓库身份应用 | 批量应用写本地配置 |
| 身份档案管理 | → | 提交历史身份审计 | 作者对照档案匹配 |
| 身份档案管理 | → | 环境体检 | 体检读取档案中的地址重写 |
| 凭据管道 | → | 环境体检 | 体检复用助手在位探测 |
| 远程与镜像 | → | 仓库配置扫描 | 扫描行展示远程/镜像状态 |

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 身份 | 一套可复用的提交者档案 | 匹配键为 name+email |
| 档案库 | 本机全部身份的持久化集合 | 与 git 配置分离 |
| 手配 | 生效 name+email 未命中任何档案 | 扫描 ⚠ |
| 配置缺失 | 生效 name 或 email 未设置 | 扫描 ✗ |
| 本地覆盖 | 仓库本地设置了 name 或 email | 标记 ◆ |
| 目录绑定 | 档案声明的目录树经 includeIf 生效 | 扫描标记 ▣；介于 local 与 global |
| include 片段 | gitid 生成的独立 gitconfig 切片 | 不进 ~/.gitconfig 正文 |
| 收编 | 把手配配置写入档案库 | 不改 git 配置 |
| 批量应用 | 对多个仓库写入同一档案的本地配置 | 全量覆盖 |
| 历史污染 | 提交作者邮箱与期望身份邮箱不同 | 只标注不改写 |
| mailmap 建议 | 展示用的作者归一化文本 | 不自动写文件 |
| 签名格式 | 身份声明的签名体系 | openpgp / ssh / x509 |
| 环境体检 | 对本机 git/助手/SSH/重写的只读检查 | 不写配置 |
